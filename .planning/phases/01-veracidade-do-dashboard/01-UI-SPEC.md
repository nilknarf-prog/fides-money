## Spacing Scale

This project uses raw CSS values, not a utility-class scale. The tokens below are the effective
scale observed in `fides-studio.css` and enforced for all additions in this phase:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, tight inline spacing |
| sm | 8px | Row gaps in lists (`fds-cats-list gap: 8px`) |
| md | 16px | Default element spacing, sidebar gaps |
| lg | 24px | Section-level padding (card bodies) |
| xl | 32px | Layout column gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level vertical rhythm |

Exceptions for this phase:
- Touch targets: any interactive element on the donut SVG (`<path>`) must satisfy a minimum
  44px tap target on mobile. The donut is 184px diameter with 24px thickness ring — each arc
  path spans a chord wide enough to satisfy this at ≥3 categories; executor must verify with
  real data (mês com 3+ categorias).

## Typography

All type roles are declared in `assets/tokens.css` and `assets/fides-studio.css`. This phase
does not introduce new type roles. Existing roles used by affected components:

| Role | Size | Weight | Line Height | CSS var | Usage in this phase |
|------|------|--------|-------------|---------|---------------------|
| Donut label | 10.5px | 600 | 1.2 | `.fds-donut-label` | Category name + "%" line in active slice; "Total" in default state |
| Donut value | 18px | 600 | 1.1 | `.fds-donut-value` | R$valor in active slice (compact BRL) |

Rules for this phase:
- Active slice display in donut center: three stacked lines using existing `.fds-donut-label`
  (category name, top) + `.fds-donut-value` (R$val, middle) + `.fds-donut-label` (percentage,
  bottom). Reuse the exact existing CSS classes — do not create new ones.
- "Sem limite" text in budget card: render with `.stu-budget-pct` class (matches the "%" slot)
  but without the `over` or `near` modifier classes. Font size follows the existing pct element.
- Percentage in donut center: format as `{N}%` (integer, Math.round). Same class as category
  name label (`.fds-donut-label`).

## Color

Canonical tokens from `assets/fides-studio.css` (`.fds-studio` scope):

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F4F5F1` (`var(--bg)`) | Page background, sidebar background |
| Secondary (30%) | `#FFFFFF` (`var(--card)`) | Cards (hero, budget card, donut card) |
| Accent (10%) | `#2D5A3D` (`var(--accent)`) | See reserved list below |
| Positive / OK | `#2D5A3D` (`var(--ok)`) | Positive saldoProjetado hero amount color |
| Destructive / Bad | `#9B2C2C` (`var(--bad)`) | Negative saldoProjetado hero amount color; "no vermelho" text |
| Warning | `#B45309` (`var(--warn)`) | Donut arc accent tint (existing, unchanged); "over" budget state |
| Muted | `#7A857C` (`var(--muted)`) | Donut labels, budget meta text, "Sem limite" text |

Accent (`var(--accent)`) reserved for:
- Positive hero amount (`saldoProjetado >= 0` → color: `var(--accent)`)
- Active/hover sparkline ticks
- Chapter marks and section dividers (existing, untouched)

Do NOT apply accent to:
- Donut slice paths (they use `a.tint` computed from category color palette)
- Inactive donut slices when a slice is active (use opacity: 0.55, not a color change)
- "Sem limite" label (use `var(--muted)`)

**Active slice opacity rule (R2):** when a slice is active (`activeIdx != null`), all OTHER
paths render at `opacity: 0.55` with `transition: opacity 0.15s`. The active path stays at
`opacity: 1`. This is the only visual change to donut paths — no fill color change, no stroke.

**Fluxo negativo warning (R3 + P1):** when `saldoProjetado >= 0` but `fluxoMensal < 0`,
the existing Receitas/Despesas/Em aberto metric grid already communicates the negative flow.
No additional color treatment is required beyond what those metrics already show. The `var(--bad)`
color is reserved for the hero amount when `saldoProjetado < 0`; it does not apply to the
metric grid values in a mixed-signal month.

## Component Inventory

Components touched by this phase (no new components created):

### 1. `Donut` — `assets/fides-charts.jsx:116-151`

**Change:** Add `onActiveSlice` optional prop + `activeIdx` useState + pointer handlers on paths.

| State | Visual |
|-------|--------|
| Default (no active slice) | All paths at opacity 1; center shows "Total / {fmtBRL(totalSpend, compact)}" |
| Hover enter (desktop) | Hovered path stays opacity 1; other paths fade to opacity 0.55 (transition 0.15s); triggers `onActiveSlice(arcs[i])` |
| Hover leave (desktop) | All paths return to opacity 1; triggers `onActiveSlice(null)` |
| Tap (mobile) | Same as hover enter; tap same slice again → deactivate (toggle) |
| Tap outside (mobile) | Document pointerdown listener outside `donutWrapRef` → deactivate |

**Cursor:** `cursor: pointer` on all paths (added via style prop).

### 2. Donut center — `assets/fides-studio.jsx:828-830` and `assets/fides-dashboard.jsx:250-252`

**Preservation constraint:** `.fds-donut-center` has a pre-existing `margin-top: 2px` applied
between the label and value lines in the existing CSS. Do not change this value. When adding
the third line (percentage) for the active slice state, do not introduce a new margin — let the
third line inherit the same `margin-top: 2px` rhythm already established by the class.

**Change (studio only):** `fids-studio.jsx` wires `activeSlice` state from `Donut.onActiveSlice`
callback and renders conditional center content.

| State | Center renders |
|-------|----------------|
| No active slice | `<div class="fds-donut-label">Total</div>` + `<div class="fds-donut-value">{fmtBRL(totalSpend, {compact:true})}</div>` |
| Active slice | `<div class="fds-donut-label">{activeSlice.label}</div>` + `<div class="fds-donut-value">{fmtBRL(activeSlice.val, {compact:true})}</div>` + `<div class="fds-donut-label">{Math.round((activeSlice.val / totalSpend) * 100)}%</div>` |

`fides-dashboard.jsx` center is NOT changed — `onActiveSlice` prop is optional; that consumer
continues rendering its own static center.

### 3. Budget card — `assets/fides-studio.jsx:~854-877` (stu-budget-list render)

**Change:** Render group state when `g.limit === null`.

| State | Renders |
|-------|---------|
| Group has limit | Existing: % real (e.g., "73%"), ProgressBar filled, "limite R$X,XX" |
| Group has no limit (`g.limit === null`) | "Sem limite" in pct slot, ProgressBar at value=0, "sem limite definido" in meta slot |

### 4. Hero — `assets/fides-studio.jsx:~724-731` (headline) and `~652` (saldoProjetado)

**Change:** Replace `saldoFinal` with `saldoProjetado` formula; keep `fluxoMensal` for P1.

| Condition | Headline copy |
|-----------|---------------|
| `saldoProjetado >= 0` | "Você terminará {Mês} com R${int},{dec} livre." |
| `saldoProjetado < 0` | "Você fechará {Mês} com −R${int},{dec} no vermelho." |

Color of the hero amount: `var(--accent)` when ≥0, `var(--bad)` when <0.

## Interaction Contract

### R2 Donut — Hover/Tap Reveal

| Trigger | Platform | Action | Dismiss |
|---------|----------|--------|---------|
| `onMouseEnter` on `<path>` | Desktop | Show active slice in center | `onMouseLeave` → restore "Total" |
| `onPointerDown` on `<path>` | Mobile | Show active slice in center; toggle off if same slice | Tap outside `donutWrapRef` via `document.addEventListener('pointerdown', ...)` |

**Transition:** `opacity: 0.55` with `transition: opacity 0.15s` on inactive paths. No other
animation. No entrance/exit animation on center content swap (instant replace is correct for
this compact 184px donut).

**Pointer events note:** `.fds-donut-center` has `pointer-events: none` (fides.css:613). The
dismiss listener must be on `document`, not on the center div. Use `useEffect` with cleanup
(PATTERNS.md §Dismiss pattern). The `donutWrapRef` ref must be attached to the `.fds-donut-wrap`
div in fides-studio.jsx to scope the outside-tap detection.

**iOS 400×512px constraint:** floating tooltip is prohibited. Center display is the only
approved surface (CONTEXT.md D-03, approved by user).

### R1 Budget Card — No-limit State

No interaction change. The "Sem limite" state is a static render, not a click target. The
ProgressBar renders `value={0}` when no limit — barra vazia, not hidden.

### R3 Hero — saldoProjetado

No interaction change. The hero amount is read-only display. Headline alternates automatically
based on sign of `saldoProjetado`. No animation on sign change.

## Accessibility

| Concern | Requirement |
|---------|-------------|
| Donut slice interactivity | Each `<path>` must have `aria-label="{category} — {fmtBRL(val)} — {pct}%"` for screen readers. Apply alongside the event handlers. |
| Color-only distinction | Active vs inactive slices differ by opacity, not color only — acceptable. The center text is the primary identification mechanism; opacity is reinforcement only. |
| Focus management | This phase does not add keyboard navigation to the donut (out of scope). Do not add tabIndex to paths. |
| "Sem limite" text | Must not be communicated by color alone; the literal text "Sem limite" / "sem limite definido" carries the meaning. |

## Constraints Carried Forward

All from SPEC.md and CONTEXT.md — listed here as executor reminders:

1. **No external libs.** Tooltip = React state + JSX + existing CSS classes. No npm install.
2. **400×512px iOS Safari rule.** Center-of-donut display enforced. Floating tooltip prohibited.
3. **`onActiveSlice` is optional prop** — `onActiveSlice?.(...)` — so `fides-dashboard.jsx`
   continues working without changes.
4. **Do not render center inside Donut SVG.** Center stays as HTML outside the SVG in the consumer.
5. **Prohibition P1:** do NOT remove Receitas/Despesas/Em aberto metrics from the hero when
   adding saldoProjetado. The `fluxoMensal` variable must be kept and remain visible.
6. **Settled transactions excluded from saldoProjetado.** Only `!t.settled && !t.isTransfer`
   pending transactions are applied over `saldoContas`.
7. **`accounts` and `cards` are separate arrays.** No type filter needed to exclude cards from
   `saldoContas` — `accounts.reduce((s, a) => s + (a.balance || 0), 0)` is correct as-is.
