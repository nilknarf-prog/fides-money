## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-07 | Tampering | validação de prazo (data passada) | mitigate | Input `type=date` com `min={hoje}` bloqueia datas passadas no cliente (D-04, validação nativa iOS Safari). RESÍDUO ACEITO (L1): banco/RLS não força `target_date >= hoje` — usuário determinado pode via API enviar data passada; risco desprezível (dado só do próprio usuário, sem impacto de segurança) |
| T-07-08 | Tampering | valor alvo (numérico) | mitigate | Input `type=number` `min=0`; `parseFloat(...) || 0` no modal e `Number(g.alvo) || 0` no store coagem valor; sem injeção (Supabase client parametriza) |
| T-07-09 | Elevation of Privilege / IDOR | editar/excluir por id de outra meta | mitigate | editTarget/deleteTarget vêm do `.map` das metas do próprio usuário (goals já filtrado por user_id no fetch); RLS `for all using (auth.uid() = user_id)` (schema.sql L142) é o controle final — update/delete de meta alheia é bloqueado pela política |
| T-07-10 | Information Disclosure | XSS via nome/descrição da meta | mitigate | React escapa por padrão todo texto renderizado (`{m.nome}`, `{m.descricao}`); sem `dangerouslySetInnerHTML` no caminho de metas |
| T-07-SC | Tampering | npm/pip/cargo installs | mitigate | N/A — nenhum pacote instalado (front sem bundler; edição de JSX in-file); sem gate de legitimidade |
