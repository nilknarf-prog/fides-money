## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser (PlnMesInsights) → /api/assistant | Client sends the user JWT + a budget context string across the network; endpoint is authenticated and rate-limited server-side |
| /api/assistant → Gemini | Server-side; out of scope for this phase (no backend change). Client only sees the shaped `{ reply }` / `{ error }` / `{ tool_calls }` response |
| Gemini response text → DOM | Untrusted model-generated text is rendered into the result panel |

## STRIDE Threat Register (ASVS L1, block-on: high)

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Information Disclosure | JWT handling in `handleAiClick` | mitigate | JWT is read from `window.fidesAuth.getSession()` and passed only in the request body; it is NEVER written to `console.*`, never rendered into `.pln-mi-ai-result`/`.pln-mi-ai-error`, and never stored in state. Acceptance criterion in Task 3 asserts no JWT logging/rendering. |
| T-05-02 | Tampering / XSS | Rendering `data.reply` (untrusted Gemini output) into the DOM | mitigate | Reply is rendered strictly as text: `aiResult.split('\n').map(line => React.createElement('p', ..., line))`. No `dangerouslySetInnerHTML` (asserted by negative grep in Task 3 verify). React text children auto-escape, so injected markup cannot execute. |
| T-05-03 | Denial of Service | Rate-limit / `USER_DAILY_LIMIT` path (429) | mitigate | 429 responses are surfaced as friendly copy via `friendlyAiError` (`USER_DAILY_LIMIT` and generic `RATE_LIMIT` distinct strings); the button re-enables (loading reset) so the user is never stuck. Server enforces the actual limit (`USER_DAILY_LIMIT=100` in api/assistant.js) — client only reflects it. |
| T-05-04 | Denial of Service | fetch hang / never-resetting loading state | mitigate | Never-hang guarantee: every branch (`!res.ok`, empty reply, `tool_calls`, network catch) resets `aiLoading=false` before returning, mirroring `fides-claude.jsx`'s `send()`. An unexpected `tool_calls` response fails closed with a friendly error rather than looping. |
| T-05-05 | Spoofing / Elevation | Auth via JWT (session expiry) | accept/mitigate | JWT is validated server-side (`supabase.auth.getUser(jwt)` → `JWT_INVALID`). Client maps `JWT_MISSING`/`JWT_INVALID` to "Sessão expirada. Atualize a página…" — no privileged action is taken client-side; read-only analysis only. Low residual risk. |
| T-05-SC | Tampering | npm/pip/cargo installs | accept | No new package installs in this phase. `@supabase/supabase-js` (used server-side by api/assistant.js) is already an existing, unchanged dependency. No package legitimacy checkpoint required. |

All high-severity threats (T-05-01 disclosure, T-05-02 XSS) have concrete, testable mitigations wired into task acceptance criteria — none left unmitigated.
</threat_model>
