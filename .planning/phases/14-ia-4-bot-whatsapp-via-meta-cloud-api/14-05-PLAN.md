    - GET: ler `req.query['hub.mode']`, `['hub.verify_token']`, `['hub.challenge']`. Se `mode === 'subscribe'` e `verify_token === process.env.WA_VERIFY_TOKEN` → `res.status(200).send(challenge)` em TEXTO PURO (nunca res.json — Pitfall 2). Senão `res.status(403).end()`.
    - POST: PRIMEIRO `const rawBody = await readRawBody(req)` (NUNCA tocar req.body antes — Pitfall 1). Só então `const payload = JSON.parse(rawBody.toString('utf8'))` (try/catch → 200 e sai, corpo malformado não é retry-able).
    - Extrair `value = payload.entry?.[0]?.changes?.[0]?.value`. Se não houver mensagem (status update, etc.) → `res.status(200).end()` e sai (Pitfall: payload não-mensagem = 200, ignora). Extrair a primeira mensagem: `from` (E.164 sem +), `wamid` (message id), `text.body`, `timestamp`.

Se já existia (conflito) → 200 e sai (retry da Meta, no-op).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Meta / internet pública → POST /api/whatsapp | Corpo não confiável; HMAC é a única autenticação do request. |
| phone (do payload) → identidade de usuário | O número da mensagem é resolvido a profiles.phone; premium decide acesso ao LLM. |
| webhook → Supabase (service_role) | Client privilegiado; RLS bypassada — filtros por user_id/phone são explícitos. |
