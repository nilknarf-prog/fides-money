    Criar `api/wa-link.js` (Serverless CommonJS, `module.exports = async (req, res)`). Fluxo, na ordem load-bearing:
    - Só aceita `POST`; senão 405 `METHOD_NOT_ALLOWED`.
    - `Cache-Control: no-store`.
    - Extrai Bearer do header `authorization` (mesma forma de assistant.js:207-208); sem token → 401 `JWT_MISSING`.
    - Cria client ANON (`NEXT_PUBLIC_SUPABASE_URL` + `NEXT_PUBLIC_SUPABASE_ANON_KEY`) e `auth.getUser(token)`; inválido → 401 `JWT_INVALID`. `userId = userData.user.id`.
    - Lê `profiles.plan` fail-closed (default 'free' em qualquer erro/linha ausente/valor desconhecido); `isPremium = plan === 'pro' || plan === 'family'`. Se `!isPremium` → 403 `PREMIUM_REQUIRED` (camada 2 do gating, AC-01).
    - Só ENTÃO instancia o client `service_role` (de `SUPABASE_SERVICE_ROLE_KEY`, persistSession:false) — wa_link_codes é REVOKE de authenticated, então a escrita exige service_role.
    - Gera um código de posse curto e legível (ex.: `crypto.randomBytes` → base32/alfanumérico de 6-8 chars, evitando caracteres ambíguos). Insere em `wa_link_codes` `{ code, user_id: userId, expires_at: now + 30 min }`. Opcional: invalidar códigos anteriores não-consumidos do mesmo user (delete/expire) para não acumular.
    - Monta o link `wa.me`: `https://wa.me/${process.env.WA_WABA_NUMBER}?text=${encodeURIComponent('Conectar Fides ' + code)}` (texto pré-preenchido que o webhook reconhece como pedido de vínculo).
    - Responde 200 `{ code, wa_link, expires_at }`.
    - try/catch raiz logando `[wa-link]` e 500 `INTERNAL_ERROR` (mesmo padrão de assistant.js:473-476).
  </action>
