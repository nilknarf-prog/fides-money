  <behavior>
    - verifySignature(rawBody=Buffer, header='sha256=<hex correto>', secret) → true.
    - verifySignature com header de assinatura errada → false.
    - verifySignature com header ausente ou sem prefixo 'sha256=' → false.
    - verifySignature onde o comprimento do hex difere do esperado → false (sem lançar).
    - readRawBody(req) resolve um Buffer com os bytes exatos recebidos do stream.
  </behavior>
  <action>
    Criar `api/_lib/whatsapp/signature.js` (CommonJS não-roteável, prefixo `_lib`), exportando:
    - `readRawBody(req)`: retorna Promise<Buffer> lendo `req.on('data')`/`req.on('end')`/`req.on('error')`, concatenando chunks (Pattern 1 do RESEARCH.md). NÃO acessar `req.body`.
    - `verifySignature(rawBody, signatureHeader, appSecret)`: retorna boolean. Rejeita se header falsy ou não começa com `'sha256='`. Calcula `crypto.createHmac('sha256', appSecret).update(rawBody).digest('hex')`, compara o hex esperado com o fornecido (após remover o prefixo) via `crypto.timingSafeEqual` sobre Buffers de MESMO tamanho — checar `.length` antes e retornar false se diferirem (nunca `===` direto: timing side-channel, mesma regra do nonce.js).

    Criar `scripts/wa-proto-hmac.js` (protótipo Wave 0-a, Open Question 1): script Node auto-contido que (1) monta um corpo JSON simulando o payload da Meta, (2) calcula a assinatura correta com um APP_SECRET de teste, (3) chama verifySignature e imprime PASS para a assinatura correta e para 3 casos negativos (assinatura errada, header ausente, tamanho divergente). Deve rodar com `node scripts/wa-proto-hmac.js` sem env vars nem rede. Objetivo: provar a MECÂNICA de comparação isoladamente antes de ligar ao Meta real (a validação ponta-a-ponta com o App Secret verdadeiro só é possível pós-setup Meta, plano 05).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Meta (público) → verifySignature | Corpo bruto de request não confiável cruza aqui; a única prova de autenticidade é o HMAC. |
| Webhook → Gemini (serviço externo) | Prompt sai do processo; minimização garante que nenhum dado financeiro sensível (saldo/extrato) vá ao LLM. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-14-05 | Spoofing | verifySignature (comparação de assinatura) | high | mitigate | HMAC-SHA256 sobre raw body + `timingSafeEqual` sobre buffers de mesmo tamanho; guard de tamanho antes; protótipo offline prova os casos negativos. |
| T-14-06 | Information Disclosure | buildParsePrompt (dado ao LLM) | medium | mitigate | Assinatura só aceita data + listas de nomes; nunca saldos/valores/extrato entram no prompt (WA-LGPD-01 minimização). |
| T-14-07 | Tampering | Segredo de HMAC em log | low | accept | Scripts de protótipo usam secret de teste local; nenhum segredo real é logado (App Secret real só em env var, plano 05). |
| T-14-SC | Tampering | npm installs | high | mitigate | Zero pacotes novos — só builtins (`crypto`, `fetch`) e módulos internos. |
