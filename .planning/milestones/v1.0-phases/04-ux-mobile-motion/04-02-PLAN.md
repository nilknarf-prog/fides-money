<objective>
Plugar os 3 modais do escopo no hook `useModalClose` (criado na Wave 1) para que tenham animação de SAÍDA real (D-02), com cancelamento de race no re-open (D-03) e travamento de clique durante o fade-out (D-04).

Purpose: A Wave 1 criou o hook e o CSS de saída, mas nenhum modal os usa ainda. Esta plan substitui `if (!open) return null` por `if (!rendered) return null` nos 3 modais, aplica a classe `is-closing` enquanto `closing`, e roteia o fechar para `requestClose`. Implementa MOTION-01 (saída visível) nos modais `.fds-modal-backdrop` do escopo.
Output: NovaTransacaoModal, CategoriaModal e ConfirmDeleteModal (contas) com entrada+saída animadas.
</objective>

Mudanças por modal (consome `window.FidesUI.useModalClose` da Wave 1):
- Em cada um dos 3 modais: chamada `const { rendered, closing, requestClose } = window.FidesUI.useModalClose(open, onClose)` (D-01/D-02). Em `fides-contas.jsx` o modal alvo usa `onCancel` (não `onClose`) — passar `onCancel` como o callback de fechar.
- Gate de render trocado de `if (!open) return null` → `if (!rendered) return null`.
- Classe `is-closing` aplicada condicionalmente (`closing ? ' is-closing' : ''`) tanto no `.fds-modal-backdrop` quanto no `.fds-modal` da raiz de cada modal.
- Todos os handlers de fechar (clique no backdrop, botão X, botão Cancelar) chamam `requestClose` no lugar de `onClose`/`onCancel` direto. Handlers de salvar/confirmar dados (`onSave`, `onConfirm`) permanecem chamando suas funções de dados — eles também devem fechar via `requestClose` em vez de `onClose` direto, para a saída animar.
